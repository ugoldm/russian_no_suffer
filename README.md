# Русский без страданий

Первая версия домашней практики по русскому языку. Репетитор выбирает тест, выдаёт ссылку группе и видит каждую работу. Ученик вводит имя, отвечает и получает результат с разбором.

Первый тест: **ЕГЭ № 4, «Ударения без ошибок»**, шесть авторских демонстрационных упражнений с несколькими вариантами ответа. Это тренировка темы, не официальный КИМ и не проверенный преподавателем учебный комплект. Демонстрационный контент согласован для первого прототипа; перед использованием в обучении проверьте ключи в предпросмотре.

## Что работает

- Каталог с фильтром ОГЭ/ЕГЭ; первый тест и предпросмотр ключей для преподавателя.
- Создание, переименование, архивирование групп.
- Выдача теста группе или без группы, копирование ссылки, закрытие приёма новых работ.
- Прохождение на телефоне и десктопе, восстановление черновика после обновления страницы.
- Проверка на сервере, пропуски как ошибки, результат и разбор после завершения.
- Сохранение всех попыток, фильтрация результатов, просмотр исходных ответов.
- Повторная отправка одной работы не создаёт дубликаты. Повторное прохождение — новая попытка.
- Подготовленные миграции Supabase, закрытое хранение ключей и SQL-функции проверки доступа.
- Генератор SQL для проверенного контента; интерфейса конструктора/загрузки файлов нет.

## Локальная демонстрация

Нужен Node.js **24** (используется встроенный SQLite).

```sh
npm install
npm run dev
```

Откройте [приложение](http://127.0.0.1:5173/). Нажмите «Открыть демонстрационный кабинет». Добавьте группу, выдайте тест и откройте полученную ссылку в другой вкладке. Выполните работу, затем в кабинете откройте «Результаты» → «Обновить».

Локальный API слушает только `127.0.0.1:5174`. Данные хранятся в `.local/demo.sqlite` и переживают перезапуск. Ключи находятся на сервере, а не в браузере. Кабинет в деморежиме доступен без проверки личности — используйте только тестовые данные. Вход ученика и кабинет преподавателя используют разные сессии, поэтому их можно проверять в одном браузере.

**Локальная ссылка работает только на этом компьютере.** Для учеников на других устройствах необходимы Supabase и опубликованный frontend. Статическая сборка в деморежиме без локального API не является работающим общим сервисом. Демо-API не разворачивать в интернете.

## Подключить Supabase

### 1. Создать проект и применить миграции

Создайте проект в Supabase. В SQL Editor последовательно выполните целиком:

1. `supabase/migrations/001_initial.sql` — закрытые таблицы, права и серверные функции.
2. `supabase/migrations/002_demo_test.sql` — первый демонстрационный тест.

Миграция 001 выполняется один раз на новой базе. Миграция 002 повторяема и не перезаписывает опубликованную версию. Вся информация хранится в схеме `private`: не добавляйте её в список exposed schemas и не предоставляйте прямые права клиентам.

При следующем изменении базы добавляйте новую миграцию, не переисполняйте 001 и не очищайте результаты.

### 2. Настроить вход

В разделе Authentication:

- Включите **Anonymous Sign-Ins** для учеников.
- Создайте постоянного пользователя преподавателя с подтверждённым email (через Dashboard). Публичная регистрация преподавателей в приложении отсутствует.
- Скопируйте ID этого пользователя и выполните:

```sql
insert into private.teachers(user_id)
values ('UUID_ПОЛЬЗОВАТЕЛЯ_ПРЕПОДАВАТЕЛЯ')
on conflict do nothing;
```

Замените placeholder настоящим UUID. Наличие аккаунта без этой записи не даёт доступа к кабинету.

Для входа преподавателя используется **код из письма**, без перехода по magic link. В шаблоне Auth email «Magic Link» разместите код `{{ .Token }}`, например:

```html
<p>Код для входа: <strong>{{ .Token }}</strong></p>
```

Frontend вызывает `signInWithOtp` с `shouldCreateUser: false`, затем `verifyOtp`. Это не конфликтует с hash-маршрутами GitHub Pages. Проверьте адреса Site URL/Redirect URLs для локального и опубликованного доменов. Для доставки писем реальному преподавателю настройте поддерживаемый SMTP: у встроенного почтового сервиса могут быть ограничения получателей.

Настройте защиту от массового создания анонимных пользователей: Supabase поддерживает CAPTCHA, в том числе Turnstile. Включите её на стороне Supabase, укажите секретный ключ **только в Dashboard**, разрешите домены приложения в Turnstile, а публичный site key передайте в `VITE_TURNSTILE_SITE_KEY`. Если защита включена в Supabase, но ключ frontend отсутствует, анонимный вход будет отклонён. Проверьте квоты и лимиты входа для ожидаемого количества учеников.

### 3. Настроить frontend

Скопируйте `.env.example` в `.env.local` и заполните публичные настройки:

```dotenv
VITE_APP_MODE=supabase
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_PUBLISHABLE_KEY
VITE_TURNSTILE_SITE_KEY=YOUR_PUBLIC_SITE_KEY_IF_ENABLED
VITE_BASE_PATH=/
```

`.env.local` исключён из Git. **Не используйте secret key или service_role вместо publishable key.** Любое значение `VITE_*` будет видно в браузере.

Запустите `npm run dev`: в режиме Supabase запросы идут в общую базу; локальный демо-API не используется. Никакого автоматического перехода на демонстрационные результаты при ошибке Supabase нет.

Пройдите контрольный сценарий: вход преподавателя → создание группы → ссылка → работа в другом браузере → одинаковый результат ученика и преподавателя.

## Публикация

### GitHub Pages

Статический интерфейс готов к Pages; серверная часть остаётся в Supabase. Перед использованием учтите ограничения Pages для онлайн-бизнеса/коммерческого SaaS, описанные в [официальных условиях](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits). Оценка применимости к вашему использованию остаётся отдельным решением.

1. Создайте GitHub-репозиторий и загрузите код без `.env`, `.local`, `materials` и `imports`.
2. В Settings → Secrets and variables → Actions → **Variables** задайте `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, при использовании — `VITE_TURNSTILE_SITE_KEY`. Это публичные параметры.
3. В Settings → Pages выберите Source: **GitHub Actions**.
4. Workflow `.github/workflows/pages.yml` запускается при push в `main` или вручную. Он проверяет наличие Supabase, запускает тесты, собирает приложение и публикует только `dist`.
5. По умолчанию `base` — имя репозитория. Для репозитория `owner.github.io` или собственного домена измените `VITE_BASE_PATH` в workflow на `/`.
6. Проверьте прямую ссылку вида `https://owner.github.io/repository/#/homework/TOKEN`, обновление страницы и вход по почтовому коду.

Исходники демонстрационного теста содержат синтетические ключи для воспроизводимой настройки; реальные ключи в Git не добавляются. Ни демонстрационные, ни реальные ключи не включены в статическую сборку.

### Другой статический хостинг

Можно подключить GitHub-репозиторий к Cloudflare Pages: команда сборки `npm run build`, каталог `dist`, переменные из раздела выше, `VITE_APP_MODE=supabase`, `VITE_BASE_PATH=/`. SQL, результаты и логика проверки при этом не меняются. Актуальные условия и квоты провайдера проверить перед запуском.

Автоматизация публикации подготовлена. Удалённый репозиторий, проект Supabase и публичный сайт в рамках этой локальной поставки не создавались.

## Импорт следующих материалов

Передайте файл агенту в чат. Он извлечёт упражнения и ключи, покажет отчёт и создаст JSON по форме `server/demo-content.mjs` (объект теста). Рабочие исходники кладите в `materials/`, подготовленные данные и SQL — в `imports/`: оба каталога исключены из Git.

Для проверки JSON и подготовки SQL:

```sh
npm run import:sql -- materials/test.json UUID_ПРЕПОДАВАТЕЛЯ imports/test.sql
```

Команда не обращается к сети и не требует секретов. Она проверяет ID, формат, ключи, варианты и правила нормализации. SQL содержит ключи, поэтому сохранение разрешено только в `imports/`. Выполните его в закрытом SQL Editor после просмотра содержания.

Поля теста: `id` (один на экзамен/год/номер), `versionId` (новый для каждой версии), `exam`, `year`, `taskNumber`, `title`, `subtitle`, `version`, `status`, `demo`, `description`, `source`, `exercises`.

Поля упражнения: `id`, `prompt`, `type` (`multiple`, `single`, `text`), `options` (ID и текст для выбора), `key` (массив ID или допустимых строк), `explanation`, `normalization` (для текста: `trim`, `ignoreCase`), при необходимости происхождение `source` (страница/раздел). Если ключей нет — статус `draft`, а не `published`. Сочинения, изложения и сопоставления ещё не поддерживаются.

Повторный импорт идентичной версии безопасен; изменить уже существующую версию SQL не позволит. Для обновления повышайте `version` и задавайте новый `versionId`, сохраняя `id`. Новые выдачи используют последнюю опубликованную версию, старые — прежнюю. Кабинет первой версии показывает опубликованные тесты; черновики хранятся в базе до проверки и публикации через агента.

## Проверки

```sh
npm test
npm run test:db
npm run build
```

`npm test` проверяет серверное оценивание, пропуски, идемпотентность, чужие попытки, закрытие выдач, импорт и сохранение SQLite после перезапуска. HTTP-тесту нужна возможность слушать локальный порт.

`npm run test:db` применяет **настоящие SQL-миграции** к PostgreSQL в PGlite с тестовыми заменами `auth.uid()`/`auth.jwt()`, переключает роли и проверяет права, ключи, проверку, идемпотентность и неизменяемость версий. Этот тест не заменяет контрольного прохода в реальном Supabase: почтовый сервис, CAPTCHA и сетевую конфигурацию провайдера можно проверить только после его подключения.

## Данные и ограничения

Имя не подтверждает личность. Сессия ученика сохраняется в этом браузере; другой браузер или устройство создаёт другого технического пользователя. На общем устройстве нажмите «Другой ученик». Одинаковые имена не объединяют владельцев попыток. Ссылка определяет группу, но не проверяет членство; её можно переслать.

Результаты хранятся без автоматического удаления до решения владельца о сроке хранения. Для удаления конкретной работы по запросу сначала проверьте её ID и владельца в закрытой базе, затем удалите только соответствующую строку `private.attempts`; не удаляйте пользователя Auth с чужими/нужными работами. Все ответы этой попытки хранятся в самой записи. Не делайте такого удаления без явного указания владельца.
